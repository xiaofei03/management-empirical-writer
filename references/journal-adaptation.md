# Same-file journal adaptation

Use when a target journal is confirmed. If undecided, offer comparison; do not require a shortlist or decision JSON when the user has already chosen.

1. Identify the one active manuscript and preserve a Git baseline under project rules. Never create another editable mother or journal branch by default.
2. Verify relevant current official scope, article type, abstract/body limits, layout and submission-file requirements. Reuse a dated profile when valid; flag conflicting official instructions. Separate requirements from optional aesthetics.
3. Adapt only authorized scope. Formatting requests do not authorize rewriting theory. Broader repositioning preserves constructs, hypotheses, estimates, sample and evidence strength unless substantive change is authorized and supported by evidence.
4. Edit a safe temporary candidate and promote to the same path. Preserve live Zotero fields, native equations, figures and numerical values. Follow chapter-writing rules for rhetoric and scoped document/citation QA.
5. Ordinary adaptation does not generate submission files. On an explicit packaging request produce only required files, confirm declarations, anonymize appropriate file roles and unlink only upload exports when necessary. Cross-check appendix citation numbering against the delivered main file.
6. Verify rendered final equations, table borders, pagination and physical page-count interpretation for submission delivery. Inspect portal conversion when available; local rendering alone cannot guarantee portal correctness.

The active manuscript may already be anonymous. No paired work/anonymous drafts are needed. Subsequent edits still target the same manuscript; old exports are stale until requested regeneration. Preserve actual submitted artifacts read-only, not as another work file.

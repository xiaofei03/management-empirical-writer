# Project structure

Reuse the existing single active manuscript path. A new project may start with manuscript.docx, or manuscript.md during drafting; do not maintain both in parallel. At the Word transition the Markdown becomes historical.

Create only needed evidence, analysis and figure folders. Temporary candidates, probes and renders belong in _work/<run_id>/. Workflow state is optional for small tasks; reuse existing state and ledgers. Git preserves ordinary history.

Do not scaffold cn/en, per-journal, anonymous or submission trees. Adapt the same file when the destination is confirmed. Create submission/ only when an upload package is explicitly requested, with only required files. Preserve an actual submitted artifact as a read-only milestone, not a second active draft.

Existing project layouts do not authorize moving or deleting files. Keep confidential data and real manuscript materials out of reusable skill folders. Use optional templates only when relevant.
